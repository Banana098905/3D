# 性能の実測結果（1.0 → 1.1）

**読む前に**: 数値はすべて、この開発環境（Node v22 / Xeon 2.1GHz 2 コア / Linux、ブラウザは Chromium + SwiftShader）での 1 回〜数回の実測です。
あなたの端末・実 GPU・他ブラウザでの性能保証ではありません。測っていないものは載せていません。生データは `bench/results/*.json`。

## 1. 物理（既存 PhysicsWorld）— 回帰なし（同一セッション A/B）
`PhysicsWorld.step()` の実装は 1.1 で変えていません（補間・一時停止・stateHash は opt-in で既定 OFF）。念のため v1.0 と v1.1 を**同じ環境・同じ時間帯に**続けて実測しました（平均 ms/step、v1.1 ÷ v1.0）:

| 配置 | v1.0 | v1.1 | 比 |
|---|---|---|---|
| 粒子 10,000 | 1.830 | 1.873 | 1.02× |
| 粒子 100,000 | 16.719 | 17.984 | 1.08× |
| 3D 疎 30,000 | 8.816 | 8.503 | 0.96× |
| 3D 密 30,000 | 19.573 | 19.367 | 0.99× |

13 配置すべてで 0.72〜1.12×（ノイズの範囲）。**改善でも悪化でもありません。**
注意: 以前保存した `baseline-v1.0-physics-node.json` と今回の値が最大 40% 違うのは、測定時の環境の状態差です（同じコードでも変わる）。比較は必ず同一セッションで行ってください（`*-rerun.json`）。

## 2. 新・衝突システム（CollisionWorld）— 1 ステップあたり、全員が毎フレーム動く球の群れ
`node --expose-gc bench/collision-bench.mjs`。物体数 N、密度一定（1 球あたり約 8 セル分の空間）。

| N | 方式 | 中央値 ms | P95 ms | 最大 ms | 候補ペア | 接触 |
|---|---|---|---|---|---|---|
| 1,000 | hash | 0.412 | 1.595 | 4.189 | 278 | 150 |
| 10,000 | hash | 3.716 | 5.609 | 24.936 | 2,841 | 1,497 |
| 50,000 | hash | 21.057 | 23.985 | 25.494 | 14,084 | 7,376 |
| 100,000 | hash | 48.390 | 53.193 | 53.774 | 28,426 | 14,915 |
| 1,000 | tree | 0.958 | 2.653 | 4.850 | 278 | 150 |
| 10,000 | tree | 25.568 | 31.438 | 37.671 | 2,841 | 1,497 |
| 100,000 | tree | 1187.760 | 1270.675 | 1301.191 | 28,426 | 14,915 |
| 1,000 | 総当たり(基準) | 4.501 | 5.161 | 5.292 | 283 | 153 |

- **全員が動き続ける均一な群れには `hash` を使ってください。** `tree`（動的 AABB ツリー）は 10 万で約 1.2 秒/step と**実用になりません**（毎フレーム全員の挿入し直しが発生するため）。
  tree が向くのは「大きな静的物＋少数の動く物」の構成です（開発中にそのような配置で hash より速いことを確認しましたが、その数値は JSON に保存していないので、ここには載せません。必要なら再測定してください）。
- 総当たりとの照合（3,000 体 × 10 ステップ）: 真の接触 14,261 に対し **見落とし 0・余分 0・重複 0**（hash / tree とも）。
- 10 万回の生成＋削除（常時 2,000 体）: hash 4.36 µs/回、tree 16.12 µs/回。ヒープ 5.8MB → 5.8MB、スロット高水位 2,000（再利用されている）、古いハンドルは全て無効。

## 3. 高速移動体（負荷テスト C）
薄い壁（厚さ 0.1）へ、1 ステップで 0.13〜1.6 単位進む半径 0.05 の球 5,000 個 × 4 ステップ。
- 連続判定なし: 衝突 **0 件（全部すり抜け）**、53 ms
- 連続判定あり: CCD ヒット **5,438 件**、125〜145 ms（約 2〜3 倍のコスト）
※ CCD は球のみ。対象は「現在位置で静止」とみなします（動く物どうしの正確な TOI ではありません）。

## 4. 複合負荷（負荷テスト F、Node・描画なし）
衝突 20,000 体（hash）＋ パーティクル 20,000（毎フレーム 600 発生）＋ アニメーター 1,000 ＋ プロファイラ、600 フレーム。

| 区間 | 中央値 ms | P95 | P99 | 最大 |
|---|---|---|---|---|
| フレーム合計 | 9.61 | 15.18 | 18.08 | 23.09 |
| 衝突シミュ | 8.50 | 12.13 | 14.00 | 18.25 |
| パーティクル | 0.45 | 0.79 | 4.75 | 13.58 |
| アニメーション 1,000 個 | 0.60 | 5.10 | 6.78 | 14.49 |

描画（GPU）は含みません。

## 5. 長時間安定性（負荷テスト G）
常時 3,000 体、毎ステップ 20 体を削除・生成、1/3 を移動。36,000 ステップ（60Hz で 10 分相当、実時間 47 秒）。
- ヒープ 5.1 → 5.4MB（わずかな増加。リークと断定も否定もできません。もっと長い実行が必要）
- 生存数 3,000 固定、スロット高水位 3,000 固定（増えない）
- ステップ時間中央値 1.16〜1.19 ms（劣化なし）、最大 7.93 ms
- 削除済みハンドル 1,000 個のうち、まだ有効扱いになったもの **0 個**

## 6. 描画（Chromium + SwiftShader＝ソフトウェア GL。**GPU 性能ではありません**）
`node bench/render-bench.mjs`。10,000 個の箱（120,000 三角形）。CPU 側のコマンド発行時間であり、GPU の描画完了までは待っていないため、小さい値は「描画が速い」ことを意味しません。

| シナリオ | ドローコール | 転送 B/フレーム | CPU 中央値 ms | P95 ms |
|---|---|---|---|---|
| 個別メッシュ 10,000 | **10,000** | 0 | 11.4 | 31.1 |
| InstancedMesh（静止） | **3** | 0 | 0.1 | 0.2 |
| InstancedMesh（毎フレーム 1% 更新） | 3 | **8,000** | 0.2 | 1.2 |
| InstancedMesh（毎フレーム全更新） | 3 | 800,000 | 0.8 | 2.3 |
| 静的バッチング（merge） | **1** | 0 | 0.0 | 0.2 |
| InstancedMesh 100,000（カリング有効） | 16 | 0 | 0.0 | 0.2 |
| パーティクル 20,000（加算合成） | 5 | 1,600,000 | 1.1 | 4.0 |

- **差分転送の効果**: 1% だけ更新するとき、全転送より 100 倍少ない転送量（8,000 B vs 800,000 B）。ブラウザテストで「部分転送と全転送の画像は完全一致」を確認。
- 1.0 では変更のあったチャンク全体（4,096 個 × 80B）を転送していました。
- GPU 時間は `EXT_disjoint_timer_query_webgl2` があるときだけ取得されます。SwiftShader で出る値はソフトウェア描画の時間です。非対応環境では `gpu` は `supported:false`・値 `null` と明示されます。


## 1.2 剛体（RigidBodyWorld）
詳細表は [RIGID_BODY.md](RIGID_BODY.md) の「性能」。Node 実測のみ（GPU/SwiftShader/実ブラウザとは別）。要点: 1k 体で動作中 1〜8 ms、10k 体で 7〜104 ms（シーン依存）。箱の塔は全員睡眠で 0.002 ms。同配置の球では旧 PhysicsWorld のほうが速い。既存 PhysicsWorld の実装は無変更のため、1.1 の結果が引き続き有効。
